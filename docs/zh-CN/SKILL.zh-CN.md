# Su Architecture First（中文对照版）

> 这是仓库根目录英文 `SKILL.md` 的中文对照版本，方便阅读与审阅。Agent 自动发现和执行仍以根目录英文版为准；本文件不会注册为第二个 Skill。

执行最小充分的架构预检，让工作既安全又可验证：先判断应该改什么、由哪一层负责，以及什么证据能够证明结果。

只有当每个重要问题都具备真实目标、责任层与责任对象、唯一事实源、根因判断、变更类型、下一步和验证证据时，评审才算完成。

## 按风险调整深度

各种规模的工程工作都使用同一条判断主线，但分析投入应与风险相称：

- **快速判断：** 对局部、可逆、责任归属清楚的变更，简要确认结果、责任对象、变更类型和检查方式，然后继续实施。
- **完整判断：** 对复发、跨层、含糊、直接影响用户或代价较高的变更，完整执行判断顺序，并按条件加载参考资料。

架构预检不是新增审批流程。仅在用户尚未授权当前范围的实施时保持评审模式；已有授权时不要重复询问，一旦必要判断和证据明确就继续执行。

## 选择观察角度

### 工程与系统

适用于修复、功能、重构、复发故障、补丁累积、状态冲突、责任归属不清和实施规划。

- 从表面症状或需求追到能够产生它的组件和权威事实源。
- 在证据证明只是一次性故障前，优先把复发问题当作结构问题调查。
- 增加新行为前，先检查现有逻辑能否安全删除或合并。
- 如果系统能够约束，就让错误状态更难产生，最好无法产生。

### 客户与产品

适用于工程选择会影响客户可见产品、服务、工作台或工作流的情况。

- 先梳理用户价值流，再看内部组织方式或 Agent 拓扑。
- 内部协作留在内部；只向用户暴露完成任务所需的选择和状态。
- 真实执行能力优先于脚本化的成功宣称。
- 当对话是用户的主要工作时，以 Chat 为主界面；当监控是主要工作时，以仪表盘为主界面。

## 判断顺序

### 1. 确认真实目标

明确预期结果、受影响的用户或操作者、决策边界、当前授权状态，以及会改变结果的歧义。

完成标准：目标变更和范围已经足够明确，不会解决成一个相邻但不同的问题。

### 2. 检查现有系统

读取相关源码、架构、状态模型、工作流或交付物。找出每项重要事实当前由谁说了算。已有表达足够时就复用，只更新受影响的分支；仅当责任归属或边界仍不清楚时，才扩大结构图或分析范围。

完成标准：现有证据足以解释相关路径和唯一事实源；尚未证实的内容必须标明为推断。

### 3. 定位责任归属与根因

把可见症状和能够造成它的层与对象分开。必要时区分用户可见对象与内部对象。对于反复出现的问题，在接受局部解释前，先检查竞争事实源、重复逻辑、泄漏的边界、临时绕行方案和等价入口。

完成标准：每个重要问题都有责任层、责任对象、唯一事实源，以及有证据支持的根因判断。

### 4. 确定变更类型

在删除、重构、实现、隐藏、文案修改和 UI 优化中选择。删除只是候选，不是默认答案。只有证据表明目标错误、过时、重复或已被替代，而且验收或回归证据能够覆盖必须保留的行为时，才选择或实施删除。不能把“更简洁”本身当作删除理由，这项分析也不授权 Agent 删除用户已批准范围之外的内容。

保留有意义的行为，只清除已有证据支持的沉积。结构性工作应排在表层优化之前。

完成标准：每个拟议动作都有一个主要类型，而且理由与其责任层相匹配。

### 5. 定义实施与证据

按依赖顺序安排工作。开始改动前，先定义可观察的验收信号、回归检查、旧故障模式、受影响入口，以及回滚点或版本边界。

对于用户可见的交付物，要说清楚：产物在哪里、下一步是什么、由谁或什么执行、进度或结果返回哪里，以及最终保存在哪里。

完成标准：每项拟议变更都有一项检查，能够区分真正成功与“看起来像修好了”的补丁。

## 输出方式

使用足以让决策可检查的最小表达形式。始终保留这条推理主线：

```text
目标 -> 相关结构 -> 责任归属与根因
     -> 变更类型 -> 下一步 -> 验证
```

聚焦单一决策时用文字；需要反复映射多个对象时用表格；只有当关系或责任归属不画出来就难以看清时，才使用树或图。

## 条件满足时加载对应参考资料

- 系统需要稳定的分层、架构树或唯一事实源分析时，阅读 [分层模型](references/layer-model.zh-CN.md)。
- 故障复发、补丁累积、状态事实源互相竞争，或用户被迫承担临时绕行方案时，阅读 [结构性诊断](references/structural-diagnosis.zh-CN.md)。
- 多种动作混在一起或依赖顺序不清时，阅读 [变更类型](references/change-types.zh-CN.md)。
- 规划实施前，或准备宣布结构变更完成前，阅读 [回归设计](references/regression-design.zh-CN.md)。
- 仅在 AI 工作台、多 Agent 产品、文件接入、Chat-first 设计、内部任务、执行交接或工作台 UI 场景下，阅读 [AI 工作台模式](references/ai-workbench.zh-CN.md)。

## 继续执行

完成预检后，使用当前 Agent 可用的工具和方法继续工作。这个 Skill 负责选择方向与证据，不依赖其他 Skill、特定 Agent 客户端或固定的后续工作流。
