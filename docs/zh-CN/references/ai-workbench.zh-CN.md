# AI 工作台模式

仅在 AI 工作台、多 Agent 产品、文件接入、工作台 UI、执行交接或 Chat-first 判断中使用这份参考资料。

## 从用户价值流开始

常见的工作台价值流是：

~~~text
表达目标
  -> 提供材料
  -> 澄清或确认重要动作
  -> 在等待期间获得与时长相称的进度反馈
  -> 收到可直接使用的结果
  -> 继续、保存、归档或恢复工作
~~~

内部角色、路由、Job、Payload、提示词、工具调用、日志和状态迁移可以实现这条价值流，但它们不是用户正常使用产品的前置知识。

## Chat-first 是条件判断

当用户的主要工作是表达需求、提供上下文、作出决定和接收结果时，以 Chat 为主界面。当用户的主要工作是监控大量稳定指标或运行状态时，以仪表盘为主界面。

辅助导航应该回答“我现在在哪里工作”。辅助面板应该呈现当前任务、结果和少量必要上下文。高级视图或调试视图可以显示内部细节，但不能把它变成第二套必经流程。

## 用户可见对象与内部对象

典型的用户可见对象：

- 对话或请求；
- 用户提供的材料；
- 确认或决定；
- 当前任务和与等待时长相称的状态；
- 输出与下一步；
- 归档点或恢复点。

典型的内部对象：

- Job 或工作包；
- Payload 与路由分数；
- 模型提示词与工具调用；
- 执行日志与状态迁移；
- Worker 或 Agent 拓扑。

内部路由应由系统处理。只有当选择内部模式或执行者本身具有真实产品价值时，才让用户作出这项选择。

## 真实执行

只有在“已上传”“已保存”等确定性状态确实发生时，才适合使用脚本化消息。普通对话应走预定的模型路径；执行成功必须由真实工具或 Worker 的结果驱动。

生产路径应连接成完整闭环：

~~~text
请求 -> 授权 -> 执行 -> 结果 -> 返回到用户可见位置 -> 持久保存
~~~

当执行能力不可用时，应展示真实边界和有用的下一步。计时器或预设回复不能证明文件读取、图片生成、内容发布或任何其他外部动作已经完成。

## 用户可见交付物契约

对于用户关心的生成产物，要说清楚：

1. 产物现在在哪里。
2. 下一步会发生什么。
3. 由谁或什么执行这一步。
4. 进度或结果返回哪里。
5. 可长期保留的结果保存或归档在哪里。

原型阶段可以临时显示工作包，但仍然要闭合这条链。成熟产品可以把工作包留在内部，只向用户呈现确认、进度、输出和恢复能力。

## 文件接入

- 通过受支持的路径读取用户提供的文本。
- 对需要专门解析的格式，使用真实解析器或执行层。
- 除非用户主动粘贴，否则不要把文件内容塞进输入框。
- 当前层无法访问本地路径时，路由到可用的执行层，或准确说明所需交接。
- 把结果返回用户当前的工作位置，不要要求用户在模型和执行器之间手工搬运。

## 工作台回归范围

当相关功能受到影响时，检查：

- 输入框行为一致，包括发送、换行和不必要的浏览器自动补全；
- 发送后的视口稳定性；
- 当对话是主要工作时，Chat 仍是主界面；
- 侧边面板仍是辅助界面；
- Chat、导航和状态界面共享同一个权威任务状态；
- 普通对话使用预定的模型路径；
- 确定性状态消息反映真实状态；
- 不虚假宣称执行成功，也不暴露路由或内部 ID；
- 每种文件类型都使用受支持的读取路径；
- 任务、执行者、结果返回位置、保存位置、归档和恢复行为闭环；
- 上下文清理使用适合真实环境的容量信号，而不是套用一个通用的固定百分比。
